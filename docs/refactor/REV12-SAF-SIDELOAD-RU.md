# REV12 — прямой SAF Sideload (RU)

**Пути не изменены:** приложение `ru.forum.adbfastboottool`, исходники `app/src/main/java/ru/forum/adbfastboottool/`, рабочая папка `/sdcard/Download/NekoFlash`.

В утверждённой вкладке Sideload осталось две кнопки. **Выбрать ZIP** открывает системный Android DocumentsUI и передаёт совместимый ZIP через `content://` напрямую из файлового дескриптора, без копирования в рабочую папку. **Импорт** сохраняет старое, явно выбранное пользователем копирование в папку.

Sideload-host требует произвольного доступа к блокам ZIP. Перед передачей `FirmwareSource.SafDocument` проверяет наличие дескриптора, возможность seek и известный ненулевой размер. Провайдеры, которые возвращают только pipe/последовательный поток, **не поддерживаются напрямую**: приложение выдаёт сообщение об ошибке и предлагает явный импорт. Передавать ZIP через обычный InputStream без seek нельзя.

USB-логика ADB и проверка итогового Recovery сохранены. Успешная передача не равна успешной установке — финальная оценка ожидает подтверждения Recovery. Результат `UNKNOWN` нельзя превращать в `SUCCESS`.

Новые сообщения о выборе ZIP, статусах передачи и ошибках есть **по-русски и по-английски**. Технические имена, URI, названия разделов, команды и исходные пути не переводятся.

**Тесты:** structural/SHA guard для узкого изменения ADB, RU/EN, JVM random block read из файла и прежние USB/очередь/диагностика. Для проверки SAF на устройстве сначала выбрать небольшой ZIP в обычном локальном DocumentsUI и убедиться, что workspace не создаётся и не появляется копия. Отдельно проверить облачный провайдер с не-seekable документом и сообщение об импорте. Для настоящего Sideload использовать только совместимый безопасный ZIP на выделенном тестовом устройстве с восстановимой копией, не на основном телефоне.

**Не реализовано этим этапом:** прямое чтение SAF для Fastboot, тяжёлые RAW/sparse >4 ГиБ и полноценные транспортные USB stress-тесты. PR остаётся Draft до аппаратной проверки.

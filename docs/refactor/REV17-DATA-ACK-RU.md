# REV17 — проверка размера ответа Fastboot DATA

Дата: 2026-10-19. Основа: PR #2 / REV16.

## Ошибка

После `download:%08x` загрузчик возвращает `DATAxxxxxxxx`, где 8 шестнадцатеричных цифр обозначают ожидаемый им размер. В прежнем коде любой ответ типа DATA считался достаточным для начала USB-передачи. При меньшем, большем или неверно сформированном ответе это могло приводить к рассинхронизации, зависанию DATA и неоднозначному результату операции.

## Исправление

- Новый `FastbootDataReplyPolicy` строго проверяет восемь hex-цифр и точное совпадение размера с выбранным payload.
- Проверка производится **до** первой записи содержимого файла в USB.
- Охвачены `flashPartitionDetailedInternal` (включая прямой SAF/Native USBFS), `downloadAndRun` и существующий `stageAndOemUnlock`.
- При несовпадении или повреждённом ответе вызывается `markSessionBroken`: дальнейшие команды запрещены до нового Fastboot-подключения. **Никакой автоматической повторной передачи**.
- `stageAndOemUnlock` теперь также проверяет wire/device лимит до команды download.
- Ранее работавшие пути, workspace и пакет не изменены.

## Проверки

- JVM: `FastbootDataReplyPolicyTest` — точный ответ, верхний предел, маленький/большой размер, ноль, повреждённый ответ.
- `tests/check_rev17.py` последовательно запускает REV16 guards и проверяет три места установки size gate.
- GitHub build/release должны пройти structural, i18n, JVM, lint и сборку.

**Аппаратной проверки нет.** На тестовом разблокированном устройстве сначала безопасные `getvar` и выбор файла без записи. Запись или искусственные USB-сбои — только по отдельному плану восстановления.

## Не входит в REV17

Большие RAW/sparse-файлы с разбиением на чанки, Mass Flash SAF, перестройка UI, новые способы обхода OEM-ограничений.

# REV13 — прямой SAF для Быстрой прошивки (RU)

**Статус:** реализована новая транспортная ветка, нужна аппаратная проверка на разблокированном тестовом Poco X3 Pro. Это **не** отчёт об успешной реальной прошивке.

## Сохранено без изменений

- Package `ru.forum.adbfastboottool`, Kotlin-путь `app/src/main/java/ru/forum/adbfastboottool/`, рабочая папка `/sdcard/Download/NekoFlash`.
- Старый Fastboot API с `File`, включая терминал, массовую очередь и загрузку/выполнение образов.
- USBFS URB pipeline, очередь, остановка, подтверждение передачи, порча/запрет повторного использования USB-сессии после неоднозначной ошибки.
- Главное правило: нельзя незаметно сменить транспорт посреди DATA-фазы или выдать 100% передачи за подтверждение записи раздела.

## Что добавлено

В существующей кнопке «Выбрать образ» Быстрой прошивки можно выбрать (1) документ Android через SAF или (2) файл из прежней рабочей папки. Для SAF используются `content://`, сохранённое разрешение чтения, seekable-дескриптор и `fstat`; реальное содержимое **не копируется** во временный файл только ради Fastboot.

`FirmwareSource.Opened.nativeFd` остаётся действительным до завершения Fastboot DATA и окончательного ответа. `NativeUsbfsBackend` принимает либо старый путь к файлу, либо fd. JNI использует `dup(fd)`, прежний `pread` и остальной существующий URB-конвейер с подтверждением результата.

Если Native USBFS недоступен, файловый провайдер отдаёт только pipe, размер документа неизвестен или дескриптор нельзя читать произвольно, прямой SAF не запускается и отображается RU/EN сообщение с предложением выбрать локальный образ. **Нет скрытого переключения** на USB Bulk/UsbRequest посреди операции. Все новые пользовательские строки есть на двух языках.

## Осталось сделать

- Перенести `FirmwareSource` и persisted SAF grant в **массовую очередь**, сохранив порядок, корректность URI и состояние при перезапуске приложения. В REV13 массовая очередь ещё работает с локальным `File`.
- Отдельно разобраться с Fastboot large RAW/sparse: текущая реализация использует стандартную длину `download:%08x`, её 32-битный размер не поддерживает одиночную отправку более 4 ГиБ. Нельзя убирать эту проверку без корректного chunk/sparse протокола.
- Продолжить перевод старых технических сообщений из Kotlin в `values/` и `values-ru/` и разделение `MainActivity`.

## Что необходимо проверить на устройстве

Сначала безопасный неразрушающий этап: на разблокированной тестовой цели подтвердить Fastboot `getvar`, выбрать через SAF маленький тестовый образ и убедиться, что выбранное имя видно и рабочая папка не увеличилась. Сравнить выбор того же файла из `Download/NekoFlash`, смену языка, разрешения и обрыв выбора.

Настоящую команду `flash`, отмену во время DATA, unplug при записи, большие файлы и повреждение разделов **не запускать без отдельного разрешения, совместимого тестового образа, полной резервной копии и плана восстановления**. Прямую передачу по USB нельзя считать подтверждённой одним CI. PR остаётся Draft; `main` не менять.

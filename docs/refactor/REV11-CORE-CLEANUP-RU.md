# REV11 — очистка исходников, файловый доступ и локализации RU/EN

Статус: рабочая карта рефакторинга; **пакеты и пути не меняем**. База — проверенный NekoFlash 6.0.0-alpha11. **Не NekoFlash Pro.**

## Фактическое состояние на 10.10.2026

- Исходный Android package: `ru.forum.adbfastboottool`; все Kotlin/Java классы лежат в `app/src/main/java/ru/forum/adbfastboottool/`. DEBUG APK намеренно устанавливается рядом как `ru.forum.adbfastboottool.dev`.
- Рабочая папка и копии образов: `/sdcard/Download/NekoFlash` (формируется в MainActivity через `folderName = "NekoFlash"`, системную папку Downloads и `initWorkspace()`).
- `startImportFilePicker()` требует `ensureWorkspaceReady()` *до* открытия системного SAF-пикера. `importFirmwareFile(uri)` копирует весь файл в workspace. `showFileSelector()` перечисляет только файлы workspace, а исполнители принимают `java.io.File`.
- В `DeviceViewModel` было 240 записей в UI операционного плана и только 4 сообщения предупреждений Fastboot Inventory: REV11 убирает это молчаливое усечение.
- Очередь массовой прошивки больше не обрезается до 32 и не сортируется тайно (REV7). Старые диагностические сегменты не удаляются автоматически (REV8).
- `MainActivity.kt` >4200 строк, `DeviceViewModel.kt` >1800. Декомпозиция пока только частичная.

## Что именно считается искусственным запретом

- Обязательная копия firmware из любого разрешённого Android URI в `Download/NekoFlash` и требование полного доступа ко всем файлам только ради выбора файла.
- Молчаливое усечение этапов, журнала, предупреждений, списка очереди, скрытый порядок.
- Лишняя проверка-подтверждение перед стандартной командой, не вытекающая из протокола; скрытые дополнительные GUI-кнопки и неиспользуемые обработчики, которые не нужны утверждённому интерфейсу.
- Дублированная логика работы с каталогами и URI; фактические имена и пути сохраняем неизменными.

## Что нельзя удалять как «искусственный запрет»

- Исключительное владение USB/единственная активная операция на интерфейсе.
- USBFS drain/poison после прерывания, проверка фактического устройства, отсутствие слепого retry после сбоя Fastboot.
- Проверка существования/readability выбранного файла, валидность target и безопасная семантика проверенных команд.
- Неизвестный результат прошивки не превращать в SUCCESS; подтверждение устройства после re-enumeration.

## Порядок структурного рефакторинга без перезаписи движка

1. **Модель файла (без смены путей).** Сохранить `ru.forum.adbfastboottool`, каталог исходников и `/sdcard/Download/NekoFlash` без переноса данных. Разделить `WorkspaceLocation` (история/логи/экспорт) и `FirmwareSource` (выбранные `content://` или прямые File/FD). Поддержать SAF grants/DocumentFile и content resolver без обязательного копирования образа. Если исходный поток непригоден для seek/random-access — явно и обоснованно предложить fallback, а не запрещать файл по умолчанию. Большие RAW/sparse >4GiB проверять на устройстве отдельно.
2. **Интерфейс выбора.** Выбор из любого доступного пользователю источника Android; импорт как *явная* операция копирования, а не обязательное условие flash/sideload. Сохранить выбранные URI/grant и верифицировать их перед стартом.
3. **Архитектура.** Изолировать навигацию, USB status, Storage/SAF, Flash workflows, Terminal, Diagnostics/Reports, Mi Unlock от `MainActivity`, постепенно сократить God-object. `DeviceViewModel` оставить оркестратором жизненного цикла, а не файловым/визуальным монолитом.
4. **Clean-up.** Удалять legacy compatibility views, мёртвые UI callbacks и ресурсы лишь после поиска всех фактических call-site и регрессии build/test. Не возвращать уже убранные REV3/REV4/REV10 элементы.
5. **Проверка.** Отдельный DEV package и Actions CI; USB backend SHA guards не менять без причин. Перед merge на аппарате — память SAF, файл в разных провайдерах, paste/IME/PT​Y, Fastboot inventory/очередь, disconnect, большие файлы при подготовленном стенде.

## Зафиксировано пользователем 10.10.2026

- **Пути не меняем:** `ru.forum.adbfastboottool`, `app/src/main/java/ru/forum/adbfastboottool/`, `/sdcard/Download/NekoFlash`. Отдельный DEBUG-суффикс `.dev` сохраняем для параллельной установки тестовых сборок.
- **Полная локализация RU и EN:** UI, диалоги, ошибки, системные статусы и инструкции. Выбор языка уже есть; `values/strings.xml` и `values-ru/strings.xml` должны иметь одинаковые ключи и совместимые параметры форматирования. Новые пользовательские сообщения не писать строковыми литералами в Kotlin.
- Технические команды, пути, параметры, ID и имена разделов не переводить, иначе нарушится совместимость.
- Добавлен тест `tests/check_i18n.py` для равенства ключей, placeholders, количества plurals, переключения языков и неизменности путей.
- Уже существующие англоязычные строковые литералы в протоколах и UI подлежат **постепенному** переносу в ресурсы; это ещё не завершено.

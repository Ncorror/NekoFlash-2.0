# REV32 — восстановление длинной очереди Mass Flash при пересоздании Activity

Дата: 31 октября 2026. Ветка: `work/rev32-mass-queue-restore-20261031`. База: DEV `0665341eb270576e08ae217a2913ec664da028a2` (REV31). **Это изменение DEV, не релиз.**

## Проблема

В Mass Flash `RecyclerView` использует `ConcatAdapter(HeaderAdapter, FlashQueueRowsAdapter)`. Заголовок формы существует всегда (1 элемент), даже когда `ListAdapter` очереди ещё не опубликовал элементы после пересоздания экрана. У `ConcatAdapter` по умолчанию есть разрешение восстановить saved layout state; при пустых строках это позволяет LayoutManager применить глубокую позицию прокрутки к одному заголовку и потенциально потерять исходный якорь.

## Изменение

`FlashQueueRowsAdapter.stateRestorationPolicy = PREVENT_WHEN_EMPTY` **до** подключения `ConcatAdapter`. Конкатенирующий адаптер выводит итоговую политику из дочерних: пока строки пусты, состояние списка нельзя применять; когда строки появляются, стандартное восстановление снова разрешено. Форма заголовка и её отдельное сохранение через `saveFormState/restoreFormState` не меняются.

Не меняются USB, ADB/Fastboot, выполнение и порядок Flash Queue, импорт файлов, отмена операций, журналы и пути диагностик. Нет новых ограничений размера очереди и автоматической очистки данных.

## Регрессии

Расширен `InterfacePolishAndroidTest`:

- пустая очередь с заголовком обязана блокировать восстановление позиции (`PREVENT`);
- очередь на 1000 строк обязана разрешать восстановление (`ALLOW`);
- после перестановок и удаления элемента проверяется **реальный прикреплённый якорь**, а не только число элементов;
- после `ActivityScenario.recreate()` проверяются точная видимая позиция, текст строки, открытая секция Mass, доступность кнопки Execute и сохранение выбранного раздела и ручного ввода;
- дождаться завершения diff/layout перед фиксацией исходного якоря, не увеличивая время ожидания теста.

Запуск в CI: build + JVM + lint + Debug APK + Android API 26 и 34 без root. **Результаты фиксировать только после завершения GitHub Actions для точного SHA**. Воспроизведение на физическом HOST с поворотом экрана остаётся отдельной полевой проверкой.

## Основание

AndroidX RecyclerView документирует `PREVENT_WHEN_EMPTY` для отложенных списков; `ConcatAdapter` вычисляет политику на основе дочерних адаптеров. Нельзя выставлять политику на `ConcatAdapter` напрямую.

- https://developer.android.com/reference/androidx/recyclerview/widget/ConcatAdapter

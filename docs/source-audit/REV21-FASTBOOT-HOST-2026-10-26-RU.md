Дата: 26 октября 2026. Репозиторий: **Ncorror/NekoFlash-2.0**.
База REV20: `7954763ba6791cdfbc91f70941ce0b5931968444`.
Код REV21: `96c6c7f46697542ac171aba7a82d88e46d835e68`.
[Draft PR #7](https://github.com/Ncorror/NekoFlash-2.0/pull/7) направлен в ветку REV20. Серия ещё не объединена в `main`.

Ревизия исправляет подмену host-операций ошибочными wire-командами, описанную в R01 [аудита REV18](REV18-AUDIT-2026-10-25-RU.md). Подготовка образов и исполнение теперь реализованы, но **R01 не объявлен полностью закрытым**: доступность генераторов на Android-хостах, реальные bootloader/fastbootd и работа с большими образами ещё требуют проверки/доработки. Во время разработки команды на телефон не отправлялись.

## Что исправлено

| Было | Теперь | Проверка |
|---|---|---|
| `format PARTITION` отправлял `format:PARTITION`, который не создаёт файловую систему как desktop fastboot | Чтение типа/размера → настоящий mkfs → Android sparse → существующий `flashPartitionDetailed`; отдельный `erase` для format не отправляется | План без erase/несуществующей wire-команды; ext4/F2FS после независимого раскрытия sparse проверяются настоящими fsck |
| `format:TYPE:SIZE` проходил как неизвестная raw-команда | Разбирается host-синтаксис, включая пустой TYPE, hex-размер и `--fs-options` | Парсер размеров, диапазонов, опций и настоящий Activity parser |
| `-w` сводился к одному `erase:userdata`, соседняя команда могла пропасть | Один сервисный план: userdata, cache, metadata; erase + format для ext4/F2FS, erase без генератора для иных сообщённых типов; следующая основная команда сохраняется | Порядок операций, отсутствие необъявленных целей, ошибки подготовки и остановка после FAIL |
| `wipe-super` пересылался устройству как строка host CLI | Проверка metadata-only `super_empty.img`, сборка sparse-образов с geometry и всеми копиями LP metadata, flash нужных block devices | Форматы LP 10.0/10.1/10.2, независимое раскрытие образов, retrofit/all/other, повреждение SHA-256 и границ |
| `--set-active` рядом с основной командой мог игнорироваться | Входит в тот же план; следующая операция с неуказанным slot использует выбранный слот | Выбор активного/явного слота; старый протокол дополнительно проверяет фактический current-slot |
| Разные терминальные ветки отдельно запускали операции | Все Fastboot-действия терминала проходят один admission сервиса и одну проверку `-s SERIAL` | Структурный контракт и Activity parser; прежние тесты сервиса API 26/34 сохранены |
| Дополнительные аргументы некоторых host-команд игнорировались | Неподдержанный хвост явно отклоняется до выполнения; raw/OEM передаёт свою полную строку | `-w flash … reboot`, лишние аргументы erase/boot/update-super |
| Format в инструментах был заменён пояснением о незавершённой реализации | Кнопка «Форматировать файловую систему» запускает общий план; подготовка и номер текущего действия отображаются в Центре операций | XML, привязка обработчика, RU/EN, lint; внешний вид на физическом экране ещё не проверен |

Поддержан синтаксис `format[:FS_TYPE[:HEX_SIZE]] PARTITION`, `-w` отдельно или вместе с одной основной командой, `wipe-super [super_empty.img]`, `--fs-options=projid,casefold,compress`. `--slot` применяется к format/flash и metadata-целям wipe-super. Последовательность wipe, как в AOSP, обращается к userdata/cache/metadata без добавления slot-суффикса.

`fastboot raw WIRE_COMMAND` явно сохраняет доступ к командам производителя, в том числе `raw format:userdata`. После `raw` аргументы, похожие на host-флаги, не разбираются. `--` также прекращает обработку host-опций; исходное quoting OEM-аргументов сохраняется. Это не полноценный интерпретатор shell или произвольной цепочки desktop-fastboot команд.

## Подготовка, ошибки и отмена

- Все необходимые локальные образы создаются до первой изменяющей команды плана. Ошибка mkfs, повреждённый super template или неподходящий размер payload не оставляют предварительно стёртый userdata.
- Проверка размера использует **тот же** `effectiveMaxDownloadSizeBytes`, что и старый транспорт: в FastbootProtocol добавлен только потокобезопасный accessor. Учтено различие между hex-размерами разделов/format и числовым форматом `max-download-size`; повторно реализованная другая политика не используется.
- Нет нового ограничения по размеру исходного файла, списка разрешённых разделов или диалога подтверждения. Существуют реальные границы формата sparse, одного DATA download и возможности устройства. Resparse пока не реализован; превышение сообщается до erase.
- Неизвестный тип userdata прерывает wipe до изменений. Несообщённые cache/metadata пропускаются с записью в журнал. Это не подтверждение физического отсутствия этих разделов; сведения bootloader необходимо проверить на тестовом устройстве.
- Отказ обязательной команды прекращает план. Завершённые предыдущие команды не откатываются и не повторяются автоматически. Необязательный `oem allow-flash-super` для retrofit обрабатывается отдельно: его FAIL записывается, после чего пробуется запрошенный flash, как в AOSP.
- Входной LP template копируется в приватный snapshot и проверяется по SHA-256 geometry/header/tables. Непустые extent tables не принимаются как `super_empty.img`. Обычные flash-файлы по-прежнему открывает существующий движок; защита от внешней подмены файла остаётся отдельной задачей.
- Генератор запускается напрямую через ProcessBuilder, без shell. Отмена завершает процесс и дожидается выхода перед удалением файлов. Приватные временные файлы удаляются в finally; остатки прерванного процесса убираются перед следующей подготовкой образов. Обычные raw-команды не создают каталог образов.
- Пустые области RAW-файла кодируются FILL-zero, а не DONT_CARE: форматирование не должно сохранять старые байты внутри новой файловой системы. SEEK_DATA позволяет пропустить чтение дыр локального файла; при отсутствии поддержки выполняется потоковое чтение. Это не оптимизация по карте занятых блоков ext4/F2FS и может увеличить объём записи на устройстве.

## Что ещё ограничивает готовность R01

1. Генераторы **пока не входят в APK**. Ищутся исполняемые `mke2fs`/`mkfs.ext4`, `mkfs.f2fs`/`make_f2fs` в системных каталогах Android. Наличие файла не гарантирует разрешение его запуска и совместимые опции. При отсутствии/отказе инструмента операция завершается с ошибкой до erase. Termux и root для скрытого обхода доступа не используются.
2. На CI проверены Linux e2fsprogs/F2FS tools. Не проверены конкретные Android-варианты утилит, SELinux, файловая система cacheDir и SEEK_DATA на телефоне. Для предсказуемой поддержки всех хостов следующий шаг — воспроизводимая поставка совместимых генераторов для четырёх ABI либо подтверждённая матрица системных утилит.
3. ext4 создаётся с явным набором совместимых features и 4 KiB block size; для projid выбираются увеличенные inode. F2FS получает Android-профиль и соответствующие features. Это не обещание побайтно идентичного результата с каждой версией desktop fastboot/mke2fs.
4. Sparse-кодировщик создан для локальной подготовки образов. Он **не** добавляет разбиение большого существующего RAW/sparse, `-S` или увеличение wire-команды. R05 остаётся открытым.
5. Для wipe-super проверен бинарный формат на тестовых metadata fixtures, но не конкретный vendor template и физическое размещение на Poco. Требуются совместимый template и отдельный план восстановления на тестовом аппарате. Fastbootd автоматически не включается.

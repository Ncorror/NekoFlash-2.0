# REV52 — полевая регрессия ADB/Foreground Service и согласованный экспорт

Дата: 7 ноября 2026. База: REV51, `8c51a427`. Задачи [#53](https://github.com/Ncorror/NekoFlash-2.0/issues/53), [#52](https://github.com/Ncorror/NekoFlash-2.0/issues/52), [#50](https://github.com/Ncorror/NekoFlash-2.0/issues/50).

## #53 — недопустимый запуск connectedDevice без USB

Исходное доказательство: на POCO F7 (Android 16) пять команд `fastboot ...` без подключённого устройства дали Android `SecurityException: Starting FGS with type connectedDevice ... requires permissions`. Манифест **уже содержит** `FOREGROUND_SERVICE_CONNECTED_DEVICE`. Причина в порядке проверок: операция запускала foreground service до проверки действующего USB-канала.

Исправление:
- `UsbOperationAdmission`: чистая политика допуска, отдельно ANY_USB, FASTBOOT, ADB.
- `DeviceViewModel.startOperation`: проверка под тем же `operationLaunchLock` **до создания** `ServiceOwnedOperation`, записи PREPARING, запуска ForegroundService или любого USB-трафика.
- Для терминального Fastboot-плана явно требуется Fastboot, не просто подключённый ADB. Другие USB-операции должны иметь хотя бы один подтверждённый канал перед попыткой запуска службы.
- Отклонённая операция сохраняет диагностическое сообщение, не создаёт ложного состояния Операционного центра. Не добавлялись фиктивные Bluetooth/Wi-Fi/NFC-разрешения, и работа фоновой службы для реальных операций не отключалась.

## #52 — ADB shell_v2: ранний CLSE

В одном физическом прогоне команда `adb shell echo TEST_123_ABC` получила `ADB stream closed during write` и неизвестный код выхода; через десять секунд команда прошла успешно. Интерпретировать это как однозначный баг маршрутизации пакетов нельзя. 
- Дополнено диагностирование `openAdbStream` и `writeAdbStreamChunk`: локальный/удалённый ID, отправленные байты, байты буфера ответа, поколение диспетчера и состояние соединения.
- Если удалённый канал закрыт до подтверждения отправки, команда по-прежнему получает ошибку; **никакой автоматический повтор** не применяется, чтобы не продублировать потенциально разрушительное действие.
- USB-пакеты, состояние транзакций и протокол команды не изменены. Полный причинный фикс после изучения новой трассы и детерминированного воспроизведения.

## #50 — JSON, обновившийся во время архивации

`DiagnosticLogStore.writeSessionSummary` уже записывает новый JSON во временный sibling и публикует с помощью атомарной замены `FilePublication.replace`. При работе экспорта путь `session-summary-*.json` может измениться, но открытый `FileInputStream` продолжает читать **предыдущую цельную версию** файла.

- `DiagnosticEvidenceArchive` теперь сравнивает для JSON размер самого *открытого inode* до/после чтения и с количеством скопированных байт. Появление новой версии по пути не обозначается как потеря или порча экспортированного JSON: добавляется `note=ATOMIC_SUMMARY_REPUBLISHED`.
- Если содержимое открытого файла само изменилось по длине во время копирования — по-прежнему `warning=SOURCE_CHANGED_DURING_EXPORT`.
- Для остальных логов/трасс остаётся строгий контроль длины и изменения пути.
- Потоковый ZIP продолжает содержать оригинальные байты, манифест SHA-256, все сегменты и полную трассу падений, без удаления исходников. Старые журналы без пролога продолжат явно помечаться как неполные.
- Добавлен воспроизводимый JVM-тест с атомарной публикацией другой версии JSON **во время записи ZIP** и сравнением байтов старой/новой версии.

## Приёмка

1. Полный GitHub CI (структурные guards, JVM, lint, APK, API26, API34) на точном HEAD этой ветки.
2. На Android 16, **без подключённого устройства**, команда `fastboot getvar product`: короткое сообщение об отсутствии Fastboot; **никакой ошибки connectedDevice FGS** и никаких пакетов USB.
3. При ADB SYSTEM на целевом аппарате: `adb shell echo REV52_OK`, `adb shell id`, интерактивный `adb shell` и `exit`. Raw stdout/stderr сохраняются. При `A_CLSE` в логах должны быть ID и состояние; команда не повторяется сама.
4. Экспорт ZIP с многократно обновляемым `session-summary`: 100% SHA-256 для всех элементов, без ложного `SOURCE_CHANGED` при атомарной замене. Старые пропущенные прологи по-прежнему в предупреждениях.
5. **Не повторять прошивку разделов**, не удалять логи и не публиковать диагностические ZIP публично.

**Статус:** кандидат, не аппаратно принят. `main` не изменён; REV52 построен поверх REV51, а тот поверх открытого PR #45.

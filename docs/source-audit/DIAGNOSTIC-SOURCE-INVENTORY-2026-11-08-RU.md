# Дополнительная проверка исходных диагностических файлов — 8 ноября 2026

Задача: [#50](https://github.com/Ncorror/NekoFlash-2.0/issues/50). Изменяется только локальный read-only инструмент `scripts/verify_diagnostic_zip.py` и его тесты; приложение, ADB/Fastboot и алгоритм создания ZIP не меняются.

## Пробел в предыдущей проверке

До этой доработки утилита успешно сверяла SHA-256/размер каждого файла из манифеста с данными ZIP и, при наличии `--source-root`, с одноимённым оригиналом. Но если в **исходной папке был дополнительный файл `log-*.txt` / `trace-*.txt`, которого вообще нет в манифесте ZIP**, этот пропуск утилита не обнаруживала. Поэтому совпадение SHA-256 само по себе не доказывало совпадения **набора** файлов.

## Новая необязательная проверка

Опция `--check-source-inventory` сканирует предоставленные `--source-root ID=PATH` только для известных имён диагностики, используя те же префиксы, что и Android-экспортёр (log-, trace-, session-summary-, usb-, diagnostic-, session-, crash-, last-crash-marker.txt). Другие файлы, включая `boot.img`, не относятся к журналам и игнорируются. Если найден исходный диагностический файл, отсутствующий в ZIP, выводится `UNARCHIVED_DIAGNOSTIC_SOURCE` и возвращается код 1. Ошибка чтения каталога, недоступный путь или выход символьной ссылки из корня тоже не должны считаться успешной приёмкой.

Обычная проверка без этой опции сохраняет прежнее поведение. Сканер **ничего не удаляет, не извлекает из ZIP, не изменяет и не отправляет**.

Пример для Termux, когда NekoFlash завершил запись журналов и открыт доступ к их исходной папке:

```sh
python scripts/verify_diagnostic_zip.py \
  /sdcard/Download/NekoFlash-diagnostics-EXAMPLE.zip \
  --source-root '1=/sdcard/Download/NekoFlash/logs' \
  --check-source-inventory
```

Здесь `1` — лишь пример: сопоставь индекс `logs/ID/...` в `EXPORT-MANIFEST.txt` с конкретным каталогом исходников; **не угадывай**. Если исходная папка активно дописывается приложением, проверка может показать несовпадение из-за изменений между экспортом и сканированием: останови активные операции и сделай новый ZIP, не стирая старые материалы. Для app-private `filesDir/diagnostics` без разрешённого доступа через Android sandbox не пытайся обходить права.

## Ограничения и критерии приёмки

- Проверяет наличие исходных **файлов** только в явно указанных доступных корнях. Нельзя объявлять весь ZIP полным, если не сверены остальные исходные каталоги.
- Не доказывает, что каждое событие действительно было записано приложением: старую потерю пролога REV48 это изменение не восстанавливает.
- CI обязан проверять отрицательный случай: ZIP с корректным SHA и манифестом, но с дополнительным `trace-*.txt` в source root, возвращает ошибку; посторонний `boot.img` не попадает в проверку.
- Не изменяет рабочий транспорт и не публикует реальные пользовательские логи.

Статус: кандидат отдельной ветки до CI и аппаратной проверки.

# REV35 — корректное отображение UTF-8 в ADB shell

Дата: 31.10.2026. Основа: DEV после REV34, merge `9eb71510351626c5c3feb01702265719e57584e4`.

## Подтверждённый дефект кода

В `AdbProtocol.logShellOutput` отдельный USB/shell-v2 packet немедленно преобразовывался в UTF-8 через `String(data, UTF_8)`, затем делился по `\n`. Границы протокольных пакетов не совпадают с границами UTF-8 кодовых точек или строк. Например, двухчастный UTF-8 символ превращался в символы замены `�` **в отображаемом журнале**. Кроме того, визуальный вывод мог разбивать одну строку по границе пакета.

Первичные `trace-adb-shell-*-stdout.bin` / `stderr.bin` из REV31 байты хранили побайтово. Их содержимое **не** менять.

## Исправление

- `ShellOutputTextRenderer`: отдельный инкрементальный UTF-8 декодер по каждому каналу, поддержка разрезанных кодовых точек, CRLF и незавершённой строки;
- для one-shot shell/v2 раздельные состояния `stdout` и `stderr`, для shell legacy — одно состояние; текстовый хвост закрывается по завершении/обрыву операции;
- строки длиннее 8192 UTF-16 единиц выдаются несколькими **отображаемыми** фрагментами (без скрытия или ограничения сырых данных; пара суррогатов не режется пополам);
- все вызовы `record.writeStdout/record.writeStderr`, коды завершения, отмена, транспорт ADB, PTY и физическая запись разделов остаются прежними;
- интерактивный `adb shell` (PTY) и универсальные сервисы ADB в этой ревизии **не меняются**. Для них нужен отдельный тест ввода/вывода и живого prompt.

## Проверки

JVM-тесты: побайтно фрагментированная кириллица/emoji; раздельные stderr/stdout; CRLF и хвост без перевода строки; повторное завершение; длинный поток без newline с проверкой полного отображаемого текста; некорректный UTF-8 не должен падать. Source guard `check_rev12.py` разрешает только точный SHA изменённого `AdbProtocol.kt` и проверяет сохранение сырого вывода.

`CI PASS` или результаты физического USB указывать **только после** фактической проверки. `main` не меняется.

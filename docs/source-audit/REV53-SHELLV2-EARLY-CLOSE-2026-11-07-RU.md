# REV53 — shell/v2: короткая команда закрывается до ACK на CLOSE_STDIN

Дата: 2026-11-07. База: REV52, `36e48da`. Связано с [#52](https://github.com/Ncorror/NekoFlash-2.0/issues/52). Кандидат только в отдельной ветке.

## Физическое наблюдение

POCO F7 / onyx Android 16 в роли USB-хоста, POCO X3 Pro / vayu Android 14 в роли ADB-цели. Присланный приватно пользователем архив `NekoFlash-diagnostics-1794064372351.zip` проверен по SHA-256:

- 103/103 исходных файлов совпали с манифестом (CRC ZIP OK).
- Сессия `18:06:26` в `6.0.0-alpha11+cbe6cc87942f.42378890585` сохраняется целиком с правильным прологом.
- `adb shell echo REV52_SHELL_OK` упал 3/3, `adb shell echo REV52_REPEAT_OK` — 6/7. При этом `adb shell id`, `getprop` и интерактивный PTY работают.
- У всех отказов `payloadBytes=5`: shell-v2 stdin `CLOSE_STDIN` (5-байтный frame). `expectedRemote=receivedRemote`, `dispatcherGeneration=1`, `transportConnected=true`. Это указывает на ранний `A_CLSE`, а не на потерю всего USB-соединения.
- В соответствующих ADB-каналах `bufferedResponseBytes=26` для `REV52_SHELL_OK` и 27 для `REV52_REPEAT_OK`. У обоих значений точное соответствие ожидаемым пакетам `STDOUT(5+15 / 5+16)` и `EXIT(5+1)`. Полный пакет пока подтверждается косвенно по длине; исходные байты в старой реализации отбрасывались до записи stdout.
- Обновление `session-summary.json` в ZIP обозначено `ATOMIC_SUMMARY_REPUBLISHED`. Старые REV48 прологи по-прежнему честно помечены как отсутствующие.

## Исправление

Проблема в `runShellV2ForResult()`: отправка `SHELL_ID_CLOSE_STDIN` до получения вывода, затем `writeAdbStreamChunk()` принимает `A_WRTE`, кладёт данные в `stream.pending`, но при раннем `A_CLSE` возвращает `false`. Вызывающий код сразу помечает команду отказом и не читает накопленный результат.

- Только при **однократном Shell-v2 CLOSE_STDIN**, если peer действительно закрыл данный stream и в нём имеются принятые байты, продолжать чтение *уже сохранённых* frame-пакетов.
- Не игнорировать `A_CLSE` для прочих команд, SYNC, push, pull, interactive shell; не изменять транспортную отправку и не повторять исходные команды.
- По завершении протокола требовать **явный EXIT frame длиной ровно 1 байт**, без пустого/null fallback на нулевой exitCode.
- Если поток завершился с неполным буфером/нет EXIT/код ненулевой/команда отменена — операция остаётся неуспешной. Никогда не заключать об успехе по одному CLOSE или по длине буфера.
- Сохранять прежние raw stdout/stderr и диагностические журналы; преждевременный CLOSE со считанным ответом помечать как предупреждение, без ложного сообщения об окончательном сбое.
- Добавлены JVM-проверки случая 26/27 байт, отказов при null/пустом/malformed EXIT, cancellation, отсутствующем ACK/пустом буфере.
- `tests/check_rev12.py` нормализует **ровно семь проверенных правок** к бинарному хешу предыдущего REV52, затем исполняет прежние инварианты ADB-протокола; отсутствие совпадения — ошибка.

## Приёмка

1. Сборка / JVM / lint / Android API26 и API34 CI на точном HEAD ревизии.
2. На телефоне: read-only `adb shell echo REV53_SHORT_OK` повторить 5 раз. Каждый вызов должен выдать текст и `exit: 0`. Сопоставить 5 raw-мета и 5 файлов stdout, без авто-повторов.
3. Проверить `adb shell id`, интерактивный PTY (`id`, `exit`), поворот экрана, обычное отключение USB.
4. ZIP: все SHA-256, текущая сессия без предупреждения о потерянном прологе, старые предупреждения не удалять.
5. Ошибочные/неполные команды не должны превращаться в `exit 0`. Не выполнять тесты `flash`, `erase`, `format` — они не нужны для этого исправления.

## Аппаратная приёмка и полировка диагностики

На сборке CI #468 (`b44792605c98`) выполнено 10 отдельных `adb shell echo REV53_SHORT_OK`: **10/10 SUCCESS, 10/10 exit 0**, каждый вызов оставил собственные stdout/stderr/meta. В 8 из 10 удалённый peer закрыл stream до ACK на пятибайтовый CLOSE_STDIN; ответ был восстановлен из принятого буфера и подтверждён явным `EXIT=0`. Ранее эти же случаи ошибочно получали FAIL.

Приватный ZIP `NekoFlash-diagnostics-1794067550617.zip`: 35/35 исходных элементов и SHA-256 в манифесте совпадают, `CONSISTENT_SNAPSHOT`, новых `warning=` нет. Сам ZIP **не опубликован**.

Последующая полировка `AdbProtocol.kt` для случая `allowBufferedEarlyClose && buffered > 0`:
- В полной диагностике по-прежнему записывается ранний CLSE с `local`, `remote`, `payloadBytes`, `bufferedResponseBytes`, `dispatcherGeneration` и `transportConnected`. Сообщение остаётся в постоянном compact journal, не подавляется и не удаляется.
- Событие отмечено `ℹ️` вместо `⚠️`: это **потенциально восстанавливаемый транспортный факт, не окончательный исход команды**. `TerminalTranscript.select` показывает в терминале реальные ошибки/предупреждения и вывод команды; не показывает штатную служебную информацию.
- При невозможности дочитать буфер или доказать полный `EXIT`, остаётся настоящая ошибка и неизвестный/ненулевой статус, а не ложный успех. Порядок ADB-пакетов и сам алгоритм выполнения Shell не менялись; автоматического повтора нет.
- Дополнен JVM-тест `TerminalTranscriptTest`: раннее CLSE — INFO и не появляется в терминале; неисправимый случай — ERROR и виден; stdout и exit отображаются.

# REV43 — ADB push -r: потоковый обход каталогов и отмена

Дата: 1 ноября 2026. База DEV: `6c63b4e6e7342caf03538b6c0be3ea5f42d6344f` (REV42).

## Два обнаруженных дефекта

`AdbProtocol.pushDirectory` делал `localDir.walkTopDown().toList()`, а
затем два фильтра — `directories` и `files`. Перед началом передачи
в Android heap хранились три коллекции путей, что вызывает лишние
выделения памяти на деревьях с тысячами файлов.

Вторая гонка: рекурсивная передача вызывала публичный `pushFile`,
который перед **каждым** файлом выставлял `cancelled = false`.
Отмена между файлами могла затеряться.

## Исправление

- `AdbPushDirectoryWalker` выполняет **три ленивых прохода**:
  предварительная проверка/подсчёт, создание всех удалённых
  директорий, затем отправка файлов в прежнем `walkTopDown` порядке.
  Сохраняется последовательность «все каталоги перед файлами».
- Нет полного списка путей в памяти, нет нового ограничения размера
  файлов или их количества. Память обхода зависит от глубины и числа
  элементов одной директории, а не всего дерева.
- Отмена проверяется при каждом переходе и перед каждым новым файлом.
  `pushPath` сбрасывает состояние отмены **один раз** при начале операции;
  внутренняя `pushFileInternal(startNewOperation = false)` не сбрасывает
  его повторно ни для отдельного файла, ни между элементами каталога.
  Публичный `pushFile` по-прежнему начинает самостоятельную команду.
  Если Stop/отключение USB произошло во время файла, результат отмечается
  как отмена, а не как успешная передача.
- Несоответствие количества элементов между проходами фиксирует
  изменение дерева во время работы; операция не сообщает ложный успех.
- Ссылки на каталоги не обходятся во избежание циклической рекурсии.
  Ссылки на обычные файлы сохраняют прежнюю файловую семантику.
- Ошибка перечисления каталога не превращается в «пустую папку».
  Все диагностические записи и побайтовый ADB SYNC сохранены.

Три прохода добавляют операции чтения файловой системы. Это цена
сохранения предварительного подсчёта, порядка передачи и ограниченного
потребления RAM без изменения поведения USB-протокола.

## Проверки

JVM: порядок, кириллица/emoji, пустая директория, 1024 файла,
отмена посреди списка, изменение/удаление дерева, циклический symlink.
Точный Git blob исходника ADB защищён `tests/check_rev12.py`.
Также выполняются build, Android lint и инструментальные тесты API 26/34.

Реальное аппаратное HOST→TARGET испытание ещё требуется: USB detach
между файлами, большой каталог/долгая передача, восстановление после
отмены, скорость и память на бюджетном Android-устройстве.
Fastboot, SYNC wire, `main` и релизная защита не менялись.

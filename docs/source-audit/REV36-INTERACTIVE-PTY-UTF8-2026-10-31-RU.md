# REV36 — интерактивный ADB shell и UTF-8 через границы пакетов

Дата: 31.10.2026. Базовая DEV-ревизия: REV35 `b2109f7f20fb62cbcbe01f6fffaf1d3d17203e8e`.

## Проверенный по коду дефект

В интерактивном shell/v2 каждый payload для stdout/stderr поступал в `logShellOutput`, а legacy shell использовал `logServiceOutput`. Обе ветки превращали отдельный USB-пакет в UTF-8 строку. Кириллица и emoji могли портиться при разрезании многобайтового символа. При этом полноценное ожидание `\n` неприемлемо: приглашение PTY обычно не заканчивается новой строкой.

## Исправление

- У shell/v2 появились отдельные инкрементальные декодеры stdout/stderr, у legacy — один.
- На неактивном 250-мс чтении выводится уже полностью декодированный фрагмент приглашения; недостающие байты UTF-8 остаются в декодере и дополняются позже.
- При выходе по ошибке, отмене или закрытии декодеры завершают хвост. Если получен exit code, он печатается после последнего фрагмента вывода.
- Непосредственная передача stdin, Ctrl+C/D, ADB ACK/CLSE, USB, RAW-доказательства однократных команд и профессиональные функции не изменены.
- Новые JVM-тесты проверяют приглашение без newline и разрезанный UTF-8 на обоих каналах.

## Что пока не подтверждено

Аппаратный Android HOST→TARGET: IME кириллица/emoji, paste, Ctrl+C/D, долгоживущий PTY, отключение USB, устройство с legacy shell, действительная задержка prompt и проблемы при повороте. Никакой реальной прошивки не производилось.

Это изменение отображения интерактивного вывода, а не эмулятор полноценного ANSI/VT100 терминала. Исходные диагностические логи не очищаются. Security/rulesets отложены по решению команды.

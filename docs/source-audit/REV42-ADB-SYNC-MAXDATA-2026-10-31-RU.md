# REV42 — ADB SYNC записывает A_WRTE строго по CNXN maxdata

Дата: 31.10.2026. База DEV: `4d069eff9f0b0bdcef5eda980ee8066f12590405` (REV40).

## Найдено по исходнику

`AdbProtocol.pushFile` использовал `SYNC_DATA_CHUNK = 64*1024` для
логического `sync:` DATA-пакета. Функция `writeAdbStream` отправляла
весь этот пакет одним USB `ADB A_WRTE`. Но ограничение
`CNXN.arg1 / maxdata` применяется к **каждому A_WRTE**, а не к
логической записи SYNC. На старом Android peer может заявлять
`4096` байт. Следствие: корректная пересылка файла могла срываться,
хотя последовательность синхронизации верна.

REV37 уже ограничила **интерактивный** stdin; остальные ADB-потоки
её не использовали.

## Изменения

- `writeAdbStream` при необходимости разбивает исходный payload на
  последовательные `A_WRTE` по реальному `peerMaxPayloadSize`.
- Для каждого блока штатный `writeAdbStreamChunk` ожидает `A_OKAY`,
  обрабатывает встречные `WRTE/CLSE` и сохраняет pending данные как прежде.
- Вся полезная нагрузка SYNC `SEND/RECV/STAT/DATA/DONE` в том же порядке:
  **не обрезаем, не перекодируем, не вводим общий лимит файла**.
  Пустой пакет при необходимости отправляется через прежний путь.
- PTY REV37 остаётся и при необходимости использует общий safety net;
  прошивка Fastboot, native transfer, flash, sideload, журналы не менялись.
- В `tests/check_rev12.py` добавлен новый exact SHA для конкретной
  ревизии и охрана границ/ACK/сохранности `SYNC_DATA_CHUNK`.
- JVM-тест пересобирает логическую запись `DATA` на 64 КиБ из
  отдельных допустимых 4-КиБ USB-пакетов байт-в-байт.

## Проверка

Гарантия на исходники + JVM + сборка + Android API26/34.
Верификация на **реальном старом ADB-устройстве** и OTG HOST с
маленьким maxdata, отменой посреди push, detach, повторным reconnect
и сохранением файла до/после нужна отдельно. Здесь нет физического
USB-теста. Никакого изменения `main`, опубликованного релиза или
защиты репозитория.

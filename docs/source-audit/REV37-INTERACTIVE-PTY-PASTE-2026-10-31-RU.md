# REV37 — надёжная передача длинной вставки в интерактивный ADB shell

Дата: 31.10.2026, база REV36 `9ee1067668c98eefb355f51ccc7d2939eb4a3367`. Отдельная ветка, без изменения main.

## Проверенный дефект

`writeShellPacket` и `writeAdbStream` отправляли весь введённый/вставленный `ByteArray` как один ADB `WRTE`. Но AOSP ADB wire protocol требует размер payload каждого `WRTE` не выше `maxdata`, объявленного собеседником в `CNXN.arg1`. Старые устройства могут объявлять 4096 байт, а shell/v2 добавляет к stdin 5 байт внутреннего заголовка.

## Исправление

- При CNXN запоминаем объявленный устройством максимум для исходящих сообщений (при нулевом/ошибочном значении — консервативный исторический fallback 4096).
- Только интерактивный stdin разбиваем на последовательные куски по `maxdata` с вычетом 5 байт shell/v2 либо без вычета для legacy; каждый `WRTE` ожидает штатный `A_OKAY`.
- **Общий размер ввода не ограничен**. Исходные байты UTF-8, включая переносы строк и границы многобайтовых символов, передаются в том же порядке без декодирования, усечения или перестановок.
- Контроль отмены/CLSE производится перед каждой частью. Другие ADB sync/firmware transfer, PTY output, Fastboot, диагностические файлы и UI не изменяются.

## Проверки

JVM-тесты собирают миллионы исходных байт обратно из последовательности фрагментов для 4096, 262144 и 1048576, проверяют собственную длину framing, ошибки и старый maxdata.

Не выдать за физический тест: реальный Android HOST/TARGET, слабый USB, большой paste и стоп/отключение требуют отдельной проверки на устройстве. Изменение остаётся в review до полного CI и слияния REV36.

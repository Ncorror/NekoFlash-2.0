# REV54 — ADB host USB Bulk: ZLP для кратной длины (Issue #57)

Дата: 2026-11-08. Ветка `fix/rev54-adb-usb-bulk-zlp` поверх `main` (`b82af9ff`), без изменения `main`.

## Подтверждённые факты с телефонов

Стенд: POCO F7 onyx Android 16 HOST, **второй** POCO X3 Pro vayu Android 12 TARGET, загрузчик locked. NekoFlash main build CI #480.

- `adb push` 512-файлового дерева дошёл до файла #224 и получил `no ACK for WRTE local=254, remote=255, bytes=1024` после 223 переданных файлов.
- Отдельная передача того же `file-0224.bin` (1016 байт, +8 байт заголовок SYNC DATA) ещё три раза повторила отказ `no ACK for WRTE ... bytes=1024`, включая новые USB-подключения и иные номера каналов.
- Файлы 1015 и 1017 байт (+8 байт SYNC) передались успешно, **1023 и 1025 байт A_WRTE**, контрольные SHA-256 совпали на обоих телефонах. 16 МиБ Push/Pull также прошли SHA-256; проблема не в правах или отсутствии слотов Fastboot.
- При некоторых отказах запоздалое `A_OKAY` появлялось при следующем открытии stream, и отбрасывалось как устаревшее. Идентификатор 255 сам по себе не является причиной.
- USB-кабель временами физически выскакивал, но имеются зафиксированные ошибки до отключения и после повторного подключения. Проверка кандидата требует надёжного кабеля.
- Сырые ZIP тестировщика остаются приватными, публично не публиковать.

## Первичный источник AOSP

[How ADB uses USB Zero-Length Packets](https://android.googlesource.com/platform/packages/modules/adb/+/HEAD/docs/dev/zero_length_packet.md) описывает разницу направлений: adbd на устройстве принимает USB OUT пакетами, **не** основывая размер IRP на полях ADB aprotocol, и хост обязан завершать пакет ZLP, если его длина кратна `wMaxPacketSize`. Без этого прием данных может зависнуть.

Android `UsbDeviceConnection.bulkTransfer(ep, data, 0, 0, timeout)` проходит через JNI к `usb_device_bulk_transfer`, а далее через USBFS `USBDEVFS_BULK` с нулевой длиной. На телефоне нужно подтвердить, что его конкретный USB host controller реально исполняет нулевую передачу.

## Изменение

- `AdbProtocol.sendMessageInternal` после полного отправленного заголовка ADB (24 байта) и отдельно после полного отправленного тела ADB вызывает проверку кратности реальному `endpointOut.maxPacketSize`.
- Только если длина переданных USB байтов положительна и строго кратна максимальному USB пакету, отправляет **пустой USB Bulk ZLP**. Не добавляет никаких байтов к содержимому ADB.
- Оставляет `adbWriteLock`, размер `USB_BULK_CHUNK_BYTES`, ADB `A_WRTE` и ожидание `A_OKAY`, верное связывание идентификаторов, `CLOSE_STDIN`, cancellation и предыдущий рабочий Shell код неизменными.
- При отрицательном/аномальном результате ZLP возвращает **ошибку транспорта**, а не ложный успех. Нет retry, изменения тайм-аутов или удаления журналов.
- Новый проверяемый отдельно pure-JVM `AdbUsbBulkOutPolicy` и тесты 1023/1024/1025, других `wMaxPacketSize`, 24-байтного заголовка при full-speed MPS=8, нулевой длины и ошибок записи ZLP.
- Строгая проверка исходников `tests/check_rev12.py` восстанавливает точный ранее проверенный REV53 `AdbProtocol` **только из трёх точных изменений**, сверяет blob SHA и затем выполняет все прежние инварианты без отключения.

## Критерии аппаратной приёмки

1. CI: JVM, lint, Debug APK, Android instrumentation API26/API34, tester kit — все PASS, без отключённых проверок.
2. Надёжный кабель/OTG; заблокированный vayu Android12 TARGET. После установки candidate поверх main (не удалять данные) подключить ADB. Тестовые файлы — **только отдельные новые имена внутри изолированной папки** `NekoFlashQA-20261107-REMOTE`; старые тестовые данные не перезаписывать.
3. Передать **1015, 1016 и 1017 байт** в три новых отдельных файла, сверить SHA-256 на TARGET с Termux. Самый важный тест — 1016 +8 =1024 байта, ранее 3/3 FAIL.
4. Проверить многократный `adb shell echo`/shell-v2 и `adb pull` 16 МиБ, чтобы исключить регрессии в других ADB типах. После каждого шага убедиться, что следующий stream открывается без устаревшего подтверждения чужому каналу.
5. Только после одиночного PASS — отдельное новое дерево из 512 файлов (новое имя назначения!), дождаться полного Push, Pull и сравнить хеши. Повторную передачу старого каталога поверх частичных 223 файлов не считать чистым тестом.
6. Проверить корректную отмену, безопасное отключение в состоянии простоя и новый лог ZIP. Не проводить flash, erase, format или unlock.
7. Пока нет аппаратного PASS, **PR остаётся draft**, проблема #57 открыта; `main` и исходный установленный релиз не изменяются.

Примечание: ZLP соответствует протоколу AOSP, но на разных Android USB host implementation поведение 0-length bulkTransfer нужно проверить на устройстве. Не заявлять доказанный аппаратный фикс до тестов.

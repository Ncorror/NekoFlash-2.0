# REV40 — выбор текста против автопрокрутки консоли

Дата: 31.10.2026. База: DEV после REV39 merge `c5f827e47413582601ef254b73d4ab86cf52ec98`.

## Подтверждённая гонка UI

REV39 включает `textIsSelectable` на `TextView` строках терминала. Но в
`MainActivity.flushConsoleRender` автопрокрутка ранее зависела только от того,
можно ли скроллить RecyclerView вниз. При выделении текста в последней
видимой строке новый log packet мог запустить `scrollToPosition(last)`
и увести выделенный текст за экран.

## Исправление

- `ConsoleAutoFollowPolicy` запрещает автоматический follow новых строк, если
  активен выбор текста, даже когда список находится в конце.
- `MainActivity.hasSelectedConsoleText` проверяет видимые реальные
  `TextView` с непустыми selection ranges; не опрашивает чужой clipboard.
- Уже запланированный асинхронный `scrollConsoleToBottom` повторно проверяет
  выбор текста перед скроллом. Это закрывает гонку между `post` и долгим нажатием.
- Явный запрос пользователя открыть терминал может показать последние строки;
  полный raw-log и bounded on-screen transcript не меняются. Ни одна строка
  не удаляется из архивной диагностики, работа ADB/PTY/Fastboot не затронута.

## Тесты

JVM: follow при отсутствии selection и в конце списка, отсутствие прыжков
при selection, при ручном просмотре старых строк, явное открытие.

Android: существующий установленный тест уже проверяет selectable TextView;
теперь он ставит настоящую `Spannable` selection, проверяет
`hasSelectedConsoleText` и снятие selection. Число instrumented tests
не меняется (20). Эмулятор не моделирует реальный Android contextual toolbar
и не доказывает, что каждый видимый элемент останется в памяти при очень
долгом USB логе — реальное устройство тестируем отдельно.

Защиту и `main` не трогаем.

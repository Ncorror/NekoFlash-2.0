# NekoFlash 2.0 — полевой раунд Insiders, 8 ноября 2026

**Цель:** аппаратная приёмка стабильности DEV после REV54/55, диагностики и всех основных способов записи на **согласованное запасное устройство**. Отчёты сохраняем побайтово. [English](INSIDERS-DEVICE-CAMPAIGN-2026-11-08-EN.md).

## 0. Какой комплект ставим

- Нужны **два файла из ОДНОГО успешного GitHub Actions run**: Debug APK и `testbook.html`. Скачай `NekoFlash-Insiders-Tester-Kit` из зелёного запуска ветки `main` после интеграции нового раунда. Встроенный в комплект TestBook содержит точный `sourceCommit`, `runId` и SHA-256 APK. Старый опубликованный REV45 ZIP **не** является новой тестовой APK.
- Перед заменой DEV: экспортируй старые логи и JSON прогресса, проверь фактическое сохранение файлов. Оригинальный NekoFlash не удаляй.
- В HTML по умолчанию шесть безопасных заданий. «Все 43 проверки» сохраняют прежний дизайн, статусы, экспорт и RU/EN. Лабораторный раздел выбирается отдельно; в нём шесть новых `LAB-01…LAB-06`.
- Статусы: `PASS` = выполнено и подтверждено; `FAIL` = реально воспроизведён дефект; `BLOCKED` = нет устройства/бэкапа/допуска; `SKIP` = сознательно не проводили. Нет доказательства — нет PASS.

## 1. Устройства и границы

- **HOST:** POCO F7 (onyx), Android 16, NekoFlash DEV, исправный OTG/data cable.
- **Безопасный TARGET:** второй POCO X3 Pro (vayu), Android 12, **заблокированный bootloader**: только USB, ADB, безопасные `/sdcard/Download` файлы, неразрушающий Fastboot `getvar` (если доступен).
- **LAB TARGET:** отдельный POCO X3 Pro (vayu), Android 14, либо другое явно выделенное запасное устройство **только после фактического подтверждения unlocked, разметки, резервных копий и восстановления**. Не предполагай наличие A/B или `recovery`/`vendor_boot` по названию телефона.
- Не отключай OTG посреди Fastboot DATA, Sideload или записи раздела. Сценарий отсоединения выполняем **исключительно на одноразовом ADB push**.

## 2. Не разрушающие испытания — по порядку

**A. Базовая диагностика.** `SETUP-01`, `UI-01/02`, `TERM-01/02/03/04/05/06`, `USB-01`, `ADB-01/02/04/06`, `CI-01/02`. Проверить IME, русский и emoji, масштаб 130%, поворот с открытой клавиатурой и командой, видимость заголовка и вывода в теле терминала, отсутствие застрявших «100%» и ложного SUCCESS. Сохранить raw trace при любой ошибке.

**B. USB и данные.** `ADB-03` — три независимых исходных файла **1015/1016/1017 байт**, соответствующие SYNC DATA WRTE 1023/1024/1025 с 8-байтным заголовком. Передать каждый, сверить **SHA-256 на TARGET**, затем 16 МиБ push/pull и `cmp` на HOST. `ADB-08` — полный каталог **512 файлов, включая `sha256sums.txt`**, push + pull + полное сравнение по SHA-256. `ADB-09` — Stop в середине безопасной передачи; `USB-03` — физический detach во время **безопасного ADB push**, затем reconnect и обычная команда. Никаких автоматических повторов, повреждённых «SUCCESS» и удаления старых QA-каталогов.

**C. Fastboot и операции на HOST.** `FB-01/02/04` — только `getvar`, распознавание bootloader Fastboot/Fastbootd и возможных несовместимых переменных; `QUICK-01` и `MASS-01` — выбор файлов/слотов и очередь, без записи; `SIDE-01` — Cancel в выборщике, никакого ZIP; `UNLOCK-01` — интерфейс без unlock. `FILE-01`, `SAF-01/02` — выбор и точность импорта одноразовых файлов.

**D. Журналы и TestBook.** 10–30 минут безопасных операций, повторов и реконнектов; `LOG-01/03` — экспорт всех исходных журналов через APK, `EXPORT-MANIFEST.txt`, sizes/SHA-256 и проверка состава с доступной папкой (`verify_diagnostic_zip.py --check-source-inventory`). Недоступные app-private файлы не извлекай в обход Android. `LOG-02` — в Chrome через `content://` проверить копирование/ручной выбор текста, фактическое сохранение JSON и ZIP, импорт JSON. Клик не означает успешную загрузку; при ограничении браузера сохраняй сырой ZIP из APK отдельно. `REPORT-01` — запись build ID, USB кабеля, времени, FAIL/BLOCKED и полного вложения.

## 3. Подготовка тестового дерева на HOST (Termux, безопасно)

Следующие команды создают **только новые QA-файлы** в Download. Если каталог уже существует, остановись: не перезаписывай свидетельства предыдущей сессии.

```bash
termux-setup-storage
ROOT="$HOME/storage/downloads/NekoFlashQA-REV56"
if [ -e "$ROOT" ]; then echo "QA_STOP_EXISTS: выбери новый уникальный суффикс"; else
  mkdir -p "$ROOT/tree" "$ROOT/return"
  for n in 1015 1016 1017; do head -c "$n" /dev/urandom > "$ROOT/boundary-$n.bin"; done
  dd if=/dev/urandom of="$ROOT/probe16.bin" bs=1M count=16
  for i in $(seq 1 511); do
    dir=$(printf "set-%02d" $(((i-1)/32)))
    name=$(printf "file-%04d.bin" "$i")
    mkdir -p "$ROOT/tree/$dir"
    size=$((256 + (i % 13) * 173))
    [ "$i" -eq 224 ] && size=1016
    head -c "$size" /dev/urandom > "$ROOT/tree/$dir/$name"
  done
  (cd "$ROOT/tree" && find . -type f -name '*.bin' -print0 | sort -z | xargs -0 sha256sum > sha256sums.txt)
  echo "QA_READY $ROOT"
  find "$ROOT/tree" -type f | wc -l
fi
```

Должно быть **512** файлов внутри `tree`, считая `sha256sums.txt`. Для переноса через встроенный NekoFlash используй `adb push` и `adb pull` (см. `ADB-08`), а команды `cmp`/`sha256sum` запускай именно в Termux, не в терминале NekoFlash. У TARGET выбирай **свежую** папку `/sdcard/Download/NekoFlashQA-REV56-REMOTE`, не перезаписывай старые файлы. При копировании дерева обратно на HOST сравни **каждый файл** и список имён; одного счётчика 512 недостаточно.

## 4. Разрушительный раунд — отдельный допуск, не автоматический

**НИКОГДА на заблокированном TARGET Android 12 или на рабочем телефоне.** Порядок заданий строго такой:

1. `LAB-01` — независимый preflight: реальный `unlocked`, codename/product, A-only/A/B, конкретный раздел, внешние проверенные бэкапы, SHA-256 образов/ZIP, заряд, исправный кабель и проверенное восстановление. **Если хотя бы одна проверка не пройдена — все LAB BLOCKED.**
2. `LAB-02` — одна согласованная запись через Quick Flash **восстановимого** модельно-совместимого раздела с последующей фактической проверкой загрузки/Recovery. Не писать критичные bootloader/modem/persist/EFS и не применять случайные IMG.
3. `LAB-03` — корректный режим Fastboot/Fastbootd, один разрешённый раздел/слот, полный ответ после DATA, отсутствие ложного SUCCESS, затем проверка загрузки. Не угадывать активный слот.
4. `LAB-04` — Mass Flash только с заранее проверенной таблицей раздел→образ→слот→SHA-256→откат. Операции проверять **по каждой строке**, не только по 100% интерфейса.
5. `LAB-05` — реальный ADB Sideload **проверенного и совместимого** ZIP в Recovery. Подтверждать окончание по Recovery, а не по 100% передачи, затем проверять загрузку.
6. `LAB-06` — `userdata wipe/format` только на полностью ненужном уже unlocked устройстве с отсутствующими ценными данными. Сброс необратим для локальных ключей. Проверить первую загрузку и восстановление данных из внешней копии. Разблокировку не выполнять просто ради галочки.

**Перед любым реальным flash/format/sideload:** зафиксируй согласие на уничтожение данных, точную модель и раздел, SHA-256, архив бэкапа, действия восстановления и результат команды. Если операция зависла, не выдёргивай кабель и не переходи к следующей записи, пока состояние не выяснено. Восстановление делай только по плану для конкретного устройства.

## 5. Что присылать

В доверенную группу/личный чат: собранный ZIP из TestBook (если Chrome действительно его сохранил), отдельно исходный ZIP NekoFlash с `EXPORT-MANIFEST.txt`, скриншоты/видео и короткий текст `TEST ID | HOST | TARGET | build/SHA | USB | PASS/FAIL/BLOCKED | expected/actual | time | rollback`. Не публикуй приватные сырые логи, серийники, RSA, аккаунты, образы пользовательских разделов в публичных GitHub Issues.

### Критерии выпуска

Безопасная матрица и LAB-матрица должны оцениваться раздельно. Автоматический CI PASS не заменяет аппаратную проверку; физический PASS одной связки не доказывает совместимость со всеми моделями.

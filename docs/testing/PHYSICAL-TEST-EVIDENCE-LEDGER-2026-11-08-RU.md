# NekoFlash 2.0 — единый реестр физических проверок

Это компактная хронология фактов, которые влияют на текущее поведение. Это **не список заданий для повторного тестирования**. Низкоуровневые REV-срезы остаются в Git history и закрытых Issues/PR.

## 13 ноября 2026 — финальная приёмка релиза

### Fastboot format/wipe (#64)

Финальная последовательность на разблокированном vayu:
- отдельный `fastboot format userdata`: F2FS создан и передан, Fastboot OKAY, позднее Android подтвердил `sys.boot_completed=1`;
- `fastboot -w`: userdata erase/recreate, raw metadata — только erase, cache erase/recreate, reboot OKAY;
- `erase:metadata` законно занял около 17,7 с; NekoFlash дождался ответа без повторной отправки/обрыва;
- после wipe телефон дошёл до первоначальной настройки Evolution X.

**Итог: FIELD PASS.**

Ранние случаи, когда format/wipe не давал загрузить Android, остаются реальными историческими FAIL и объясняют появление исправлений, но не являются текущим verdict.

### Большой ADB Pull (#72)

POCO F7/onyx как host несколько раз воспроизвёл настоящий входящий USB `USB_IN_FAILED/EPROTO` на разных смещениях. Перебор timeout/размера URB не устранил проблему. В Legacy на том же host уже были похожие плавающие входящие отказы.

Контроль POCO X3 Pro host → POCO X3 Pro target:
- Pull `/system/framework/framework.jar`: 39 293 777 байт, итоговый SHA-256 совпал;
- Pull тестового файла 128 МиБ: PASS;
- Push 128 МиБ: PASS;
- SHA на target после Push совпал с исходным;
- повторный Pull 128 МиБ: PASS с тем же SHA.

**Итог:** общий ADB Pull — FIELD PASS. POCO F7/onyx — отдельный host-specific compatibility case.

Текущий механизм большого Pull использует устойчивые диапазоны 256 КиБ, resume после ручного reconnect и итоговую проверку SHA-256. Повреждённый пакет не отправляется повторно вслепую.

## 11–12 ноября — Sideload и Fastboot

На разблокированном vayu / OrangeFox:
- выбор ZIP стал неразрушающим; запуск отдельный и явный; выбор можно очистить;
- переходы Recovery/Sideload по USB реально наблюдались и повторялись;
- обновление/перезапуск OrangeFox наблюдались на устройстве;
- отключение Recovery около 100% остаётся `VERIFY_PENDING`, если installer SUCCESS независимо не подтверждён;
- переход в bootloader, native Fastboot handshake, reboot и последующие ADB/recovery reconnect прошли.

Политика специально консервативна: успешная передача не превращается автоматически в выдуманный INSTALL SUCCESS.

## 7–8 ноября — транспорт и UI

- Граница ADB 1024 байта была реально воспроизведена на locked vayu, исправлена и перепроверена на соседних размерах 1023/1024/1025 и рекурсивном Push/Pull 512 файлов.
- Ошибка терминала после поворота/IME была воспроизведена и затем физически перепроверена как PASS.
- Короткие shell-v2 early-close ошибки были воспроизведены, исправлены и перепроверены.
- На locked vayu, использованном для неразрушающих boundary-тестов, flash/format/wipe/unlock не выполнялись.

## Правила реестра

- Хранить цепочку FAIL → fix → PASS и не переписывать ранний настоящий FAIL задним числом.
- `VERIFY_PENDING` не равен ни SUCCESS, ни FAIL.
- CI PASS не равен аппаратному PASS.
- Процент передачи не является verdict установки.
- Сырые логи/фото могут оставаться приватными; в публичный GitHub идут санитизированные выводы и неуникальные метаданные.

# NekoFlash 2.0 — большой аппаратный тест REV9

Статус: **план испытаний, а не отчёт об испытаниях**. Репозиторий Ncorror/NekoFlash-2.0; тестируемая ветка feature/rev6-shell, PR #1 Draft, main не изменён.

## Подготовка

**Хост:** Android с USB Host/OTG. Установить только отдельный Debug APK с package ID ru.forum.adbfastboottool.dev. Оригинальный подписанный NekoFlash не удалять, не перезаписывать его данные.

**Цель:** только выделенный Poco X3 Pro с **уже разблокированным** загрузчиком. Заблокированный тестовый телефон не использовать. Полностью заряженные устройства, проверенный кабель данных USB/OTG. Нужна копия важных пользовательских данных целевого аппарата.

Скачивать только последний зелёный CI, SHA которого совпадает с HEAD feature/rev6-shell. Проверить структурные проверки REV5–REV9, Kotlin JVM unit-тесты, Android lint, assembleDebug и sha256sum Debug APK. Если новая DEV-сборка требует удалить оригинальный NekoFlash, прервать установку.

## 1. Интерфейс без USB

1. Холодный запуск, Welcome, затем фон/возврат. Проверить исходную иллюстрацию.
2. Снизу ровно пять вкладок: Главная / Прошивка / Sideload / Unlock / Настройки. Системные кнопки и жесты ничего не перекрывают.
3. Главная: реальный статус и поля устройства; никаких постоянных кнопок прошивки и Центра операций; независимые раскрытия «Расширенная информация» и «Характеристики модели». Для неизвестных сведений только нейтральные заглушки, никакой выдуманной версии Android или слотов.
4. Прошивка: три внутренних раздела: Быстрая, Массовая, Инструменты. В Быстрой раздел, образ, слот, цель, одна кнопка «Прошить», отдельно ручная «Перезагрузка». Recovery не выделен. Никаких preflight, автоперезагрузок и тестовых кнопок.
5. Sideload: только выбрать ZIP, импортировать файл и подсказка Recovery.
6. Unlock: авторизация Mi Account, предупреждение о стирании данных, состояние загрузчика, свернутые дополнительные параметры. При неизвестном статусе кнопка не активна. **НЕ выполнять Unlock**.
7. Настройки: RU→EN→RU, раздел истории и отчётов, проверить длинный текст без перекрытий.

## 2. Полноэкранный терминал

1. Открыть кнопкой >_ у USB-панели на любую из пяти вкладок. Доступная рабочая область должна заполняться терминалом, а не мини-окном.
2. Ввести/вставить длинную строку, проверить редактирование, копирование, буфер обмена и прокрутку длинного вывода (200+ строк).
3. С открытой клавиатурой нижняя строка ввода видима. Первый Back закрывает IME, следующий Back закрывает терминал и возвращает на прежнюю вкладку.
4. Повторить раскрытие/закрытие и IME resize несколько раз, в том числе после вращения дисплея, без потери текста.
5. HOST CLI по умолчанию; PTY только при явном adb shell. Терминальные команды не вызывают GUI Центр операций. Ни один ответ об отсутствии устройства не маскировать под SUCCESS.

## 3. USB ADB System — только чтение

1. На разблокированной тестовой цели включить USB debugging, подтвердить RSA-разрешение на самой цели. Проверить, что правильный телефон стал USB device, а хост остался USB host.
2. Верхняя USB-панель: ADB System при достоверном режиме, иначе честное «не определено». Нажать панель и посмотреть OTG/VID/PID/интерфейсы/разрешения, обновление.
3. Встроенный терминал: adb devices; adb shell getprop ro.product.model; adb shell getprop ro.product.device; adb shell getprop ro.build.version.release. В интерактивном adb shell выполнить id, затем exit.
4. Главная отображает действительные codename/Android. 10 раз сменить вкладку. Отсоединить USB в покое и подключить вновь; цель не должна молча заменяться первым устройством.
5. Никакой установки APK, записи файлов или опасных reboot в первом проходе.

## 4. Fastboot — только чтение

1. Вручную войти в Fastboot на уже разблокированном тестовом Poco X3 Pro, подключить USB, проверить статус панели.
2. Проверить только fastboot devices, fastboot getvar product, fastboot getvar current-slot, fastboot getvar unlocked и fastboot getvar is-userspace; отсутствие ответа не равно A-only или unlocked.
3. Проверить расчёт имени цели в Быстрой, диалоги выбора файла/слота (без запуска записи). Проверить чтение getvar и диагностику через Инструменты.
4. Переподключение в простое и USB owner. Не использовать flash, erase, format, set_active, boot, unlock, update-super.

## 5. Массовая очередь — без записи

1. Подготовить небольшие копии тестовых образов. Добавить 4–5 записей в произвольном порядке, переместить вверх/вниз и убедиться, что видимый порядок сохранился.
2. Повторное добавление того же точного имени раздела должно заменить файл НА СВОЁМ МЕСТЕ, а не создать дубль и не перенести строку в конец.
3. Имена boot_a и boot_b остаются разными целями. Добавить >32 строки в подготовительный список (можно использовать фиктивные имена ТОЛЬКО для UI), проверить, что список не обрезается. НИЧЕГО НЕ ПРОШИВАТЬ по фиктивным именам.
4. Проверить удаление и смену вкладок. Реальная последовательная прошивка и остановка при ошибке — только после отдельной подготовки безопасных тестовых разделов и образов.

## 6. Sideload и долгие операции

1. Первый проход только UI и выбор ZIP. Для действительного sideload необходим совместимый, безопасный пакет и тестовый Recovery; если его нет — NOT TESTED.
2. После передачи отчёт VERIFY_PENDING до настоящего verdict Recovery. SUCCESS только при доказанном Recovery SUCCESS; FAILED только при доказанном FAIL; UNKNOWN не выдавать за успех.
3. GUI длительной операции использует контекстный Центр с истинным прогрессом и свертыванием; терминальные команды не показывают Центр.
4. Проверить, что после закрытия/повторного запуска старые лог-сегменты не исчезают; экспорт нескольких мегабайт отчёта потоковый и очищен от серийных номеров, cookie, ключей.
5. RAW/sparse >4 ГиБ, длинные USB-сессии, 90-секундный stall, direct URI/FD и аварийные отключения во время записи **НЕ СЧИТАТЬ проверенными**, пока нет подготовленного стенда и восстановимого целевого устройства.

## 7. Граница безопасности и критерий окончания

Реальная прошивка, изменение слота, erase/format, update-super, Mi Unlock, заведомо небезопасный USB-disconnect требуют отдельного осознанного разрешения, надёжной резервной копии, совместимого тестового образа и плана восстановления. Эти тесты не выполняются автоматически.

Результат по каждому разделу: PASS / FAIL / NOT TESTED; зафиксировать SHA APK, версии Android и модель обоих устройств, используемый USB-кабель, скриншоты Главной/Sideload/Quick/Mass/Unlock/терминала/USB-шторки и sanitized логи без персональных данных. Не присылать cookies Mi, ssecurity, серийные номера и закрытые ключи.

PR #1 не сливать в main, пока CI не зелёный и аппаратный smoke/big test не выполнен. Везде различать: UI реализован, компиляция пройдена, аппаратный тест пройден — это разные статусы.
